### WHAT COUNTS AS AN OVERCLAIM (the distinction this audit is built on):
###   (a) OVERCLAIM — a universal ("all formats", "the full corpus", "every daily", "the 14-format
###       corpus") or a per-format table that silently omits formats it implies it covers. CORRECT.
###   (b) CORRECTLY SCOPED — says "the five Quick tiers", names its formats, or states its own count
###       against the registry's. NOT an overclaim however small the subset. LEAVE ALONE.
###   (c) BY-DESIGN SUBSET — a tool that only ever looked at part of the corpus on purpose and says
###       so. NOT an overclaim. LEAVE ALONE.
### Only (a) is corrected. This audit did not go looking for something to report; the honest result

These are the only two committed artifacts that assert coverage of the whole corpus. Both were
checked independently, because an unverified "all 14" written before the fix is exactly the shape
this audit exists to catch.

3.1 `fixtures/cwhit-battery-discriminator-2026-07-21.txt` — "Across all 14 formats ..."
    TRUE. Its section (2) table prints FOURTEEN rows, and the five slugless formats are all present
    by name (latebronze, bronzecapweekly, goldslotsdaily, diamondheart, liveopendaily), each with
    its own era/park. The producing tool is `tools/battery-discriminator.py` — Python, reading the
    capture files off disk directly. It never touches `buildCwhitSample`, so the legacySlug defect
    could not reach it. Its own collision line ("24 across 9 formats") is a count of formats where
    a colliding key OCCURRED, not a coverage statement — a genuine near-miss for a misreading, and
    the 14-row table two sections below settles it.

3.2 `docs/CARD_VARIANT_ELIGIBILITY.md` — "Derived from the 2026-07-21 capture corpus"
    TRUE, and this one was WORTH CHECKING: the doc was committed at 09:21 on 2026-07-22, ninety
    minutes before the fix, and its table is per-CLASS (not per-format), so a nine-format run would
    have looked identical in shape and simply reported smaller counts. REPRODUCED both ways —
    catalog `data/imports/cdmx.csv` joined to the capture files on (name, Card Value):

        run over ALL 14 formats  →  Card Type 1 "played" 712 · Sub Type LE "played" 81
        run over the 9 reachable →  Card Type 1 "played" 586 · Sub Type LE "played" 80
        the doc's committed table →  Card Type 1 "played" 717 · Sub Type LE "played" 81

    The doc matches the 14-format run (the 712-vs-717 residual is this audit's cruder name/dedup
    handling, not a coverage difference — the 9-format run is off by 131, two orders of magnitude
    more). The "1274 of 3669 are Card Type 1" and "1355 = 36.9%" figures reproduce exactly.
    ⇒ the variant-eligibility table was built over the full corpus. NOT an overclaim.

4.1 THE TWO GENUINE OVERCLAIMS — "every daily", where "daily" means four of eight. CORRECTED.

    `fixtures/cwhit-gate-sweep-2026-07-21-final-config.txt` (13e52c8, 2026-07-21 12:15)
      "G2 wOBAA ordering: PASS on every tier and every daily, and POOLED."
      "== fit-pitspread-hrbab.ts — ZERO FAILs. Every gate, every tier, every daily, both channels. =="
    `fixtures/cwhit-battery-targets-2026-07-21.txt` (5698c60, 2026-07-21 15:01)
      "HR/BABIP (fit-pitspread-hrbab): ZERO fails — every tier, every daily, both channels, ..."

    WHAT WAS ACTUALLY COVERED. Both runs come from `tools/fit-kspread-pit.ts` and
    `tools/fit-pitspread-hrbab.ts`, each of which carries a hard-coded four-entry list:
      const DAILY = ["earlygolddaily", "bronzeheartdaily", "goldcapdaily", "diamondcapdaily"]
    The corpus registry types EIGHT formats as Daily. The four never evaluated are
      diamond-heart · late-bronze · gold-slots · live-open-daily
    — which are FOUR OF THE FIVE SLUGLESS FORMATS. The blind spot in the wording coincides exactly
    with the blind spot in the builder, because the tools' own list is keyed by legacy slug too.

    WHY THIS IS (a) AND NOT (b). Each artifact does tabulate its four dailies by name elsewhere in
    the same file, which is why this is narrow. But "every daily" is a universal over a set the
    registry defines as eight, and it is the sentence a future reader will quote. The concrete live
    risk: C3 pre-registers a BUDGET-FORMAT held-out validation leg on bronze-cap-weekly and
    gold-slots. A reader who takes "hrbab passes on every daily" at face value would believe
    gold-slots had already been evaluated. It has not been — by any tool, ever.

    WHAT IS *NOT* WRONG, and the correction notes say so explicitly: no measurement is incorrect, no
    table is missing rows it claimed to have, and no fit was contaminated. Both tools were four-daily
    tools BY DESIGN (dailies are held-out evaluation legs, never fit points). This is a SCOPE-LANGUAGE
    correction, not a re-run, and nothing downstream of these two artifacts needs re-deriving.

    ⇒ DATED CORRECTION NOTES APPENDED TO BOTH, 2026-07-22. Original text untouched.

    Its measured set is FOUR eras (era-2010 / 1920 / 1939 / 1998), tabulated immediately above the

    Recorded here so it is on the record if the era span is ever quoted as load-bearing.

  THE HEADLINE, PLAINLY. No committed artifact and no memory record claims 14-format coverage while
  having reached 9. The thing the audit was ordered to look for does not exist. The program's habit
  of naming its formats in its own headers is what prevented it — B1, item A and the item-B cohort
  work all state their count against the registry's, and the item-B arbitration artifact even names
  the legacy-slug filter as the reason for its four dailies, six hours before anyone knew the slug
  was a defect. The running record had already retracted the one real overstatement ("beating
  cwhit") a day before this audit was ordered, unprompted.

  What DID slip through is smaller and of one shape: the word "daily" hardened into a four-element
  set in two summary lines while the registry defined it as eight. The four it excluded are four of
  the five formats the builder could not reach. That is not a coincidence — the fit tools' daily
  list is keyed by legacy slug, so the same optional field shaped both the code path and the
  vocabulary. The lesson worth keeping is the narrow one: after the corpus grew from 9 fixtures to
  14 captures, a collective noun that was accurate at 9 was never re-checked at 14.

  RESIDUAL RISK NOW CLOSED FOR C3. Neither gold-slots nor bronze-cap-weekly has EVER been evaluated
  by any fit or gate tool. Before b4dc2ed that was impossible; after it, it is merely undone. The C3
  pre-registration's budget-format held-out leg is therefore genuinely held-out, and the two
  corrected artifacts no longer suggest otherwise.
